# 容量確認（Python 実装の RTP 送出の限界）

作成日: 2026-09-06
目的: 設計 3.2「Python 実装で同時 20〜50 本。100 本以上が必要になった時点で RTP 送出部を Go / Rust へ差し替える」の判断材料。

## 条件

- コンテナ（4 vCPU）に FreeSWITCH（max-sessions 150、着信グループ制限 60）とアプリを同居
- 応答内線 4 本 × `max_calls: 15`、発信 5 本/秒、目標 50 通話、通話長 300 秒、75 秒間観測
- 合成音声 60 秒ループ、PCMU、監視あり（2 秒周期）

## 結果

| 指標 | 値 |
|---|---|
| 発信 / 確立 / 失敗 | 50 / 50 / 0 |
| INVITE→200 p50 / p95 | 91.7 / 94.1 ms |
| メディアセッション | 100（発信 50 + 応答 50。ポンプスレッド 2 本） |
| RTP 送出 / 受信 / 欠落 | 174,756 / 174,611 / 0 |
| 20 ms 境界からのずれ | 5 ms 超 460 パケット（0.26%）、最大 61.6 ms |
| ポンプスレッドの遅れ最大 | 18.2 ms |
| FreeSWITCH の %CPU / nlwp / channels | 23〜25% / 118 / 100 |
| ホスト全体 | 4 vCPU の余裕あり（アイドル多数） |

設計 6 章の目標「5 ms 以内を 99%」は 50 通話でも満たしている（99.74%）。最大 61.6 ms のずれは立ち上げ時の SIP 処理と重なった瞬間に出ており、
定常状態では出ていない。

## 判断

- 初版の上限 50 通話は Python 実装のままで達成できる。RTP 送出部の別言語化（Go / Rust）は **今回は行わない**
- 100 通話以上が必要になった場合は、`MediaEngine` / `MediaSession` の境界（`semishigure/media/base.py`）に別実装を差し込む。SIP 側の変更は不要
- 同時数の絶対上限（アプリ設定 50）は据え置く
