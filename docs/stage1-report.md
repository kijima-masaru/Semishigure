# 段階 1 レポート（SIP コア）

作成日: 2026-09-06
環境: この開発セッションのコンテナ（Ubuntu 24.04、4 vCPU）に FreeSWITCH 1.10.12 をソースビルドし、`deploy/freeswitch/conf` の設定で 127.0.0.1:5060 に起動。
アプリは同じホストで実行（発信 UDP 5070、応答 UDP 5080、RTP 20000〜20999）。音源は `semishigure audio synth` の合成音声（60 秒ループ、8kHz/16bit/mono）。

## 完了条件の確認

「発信 UAC → 着信グループ → 応答 UAS と通り、両端で WAV の音声が RTP で流れる」

1. 9100 が INVITE → 401 → ダイジェスト認証つき INVITE → 200 → ACK（認証往復 1 回）
2. FreeSWITCH の着信グループ 8001 が 9001〜9004 を同時鳴動 → 稼働数最少の内線が 180 → 200、他は CANCEL（487）
3. 両端で RTP を送受信。受信音声を復号した RMS が 3600〜6700（無音は 0）で、`--record-rx` の WAV でも確認済み
4. 通話長経過で 9100 が BYE → 200、応答側は BYE 受信 → 200。終了後に 4 内線の REGISTER を解除（Expires: 0 → 200）

FreeSWITCH のログに WARNING / ERROR なし。`sofia status profile internal reg` で 9001〜9004 の登録を確認。

## 読み方

- **応答時間**: INVITE→200 は 1 通話で約 55 ms、5 通話でも約 90 ms。うち 50 ms は応答側の「同時鳴動の窓」（`answerer.ring_window`。兄弟 INVITE を待って稼働数最少の内線を選ぶ）で、PBX 自体の処理は 100 Trying まで 22 ms、その後 30〜40 ms。
- **RTP 送出遅れ**: 20 ms 境界からのずれは最大 0.45 ms、平均 0.12 ms、5 ms 超は 0 件（10 セッション同時）。設計 6 章の目標「5 ms 以内を 99%」を満たす。
- **初 RTP**: 200 受信から 5〜18 ms で送出開始。受信側の負値は FreeSWITCH が 200 を返すより前（B レグ応答直後）に RTP を送り始めているため。
- **欠落**: 受信 RTP の欠落 0。
- 同時鳴動の「敗者」内線（CANCEL → 487）は統計上 `cancelled` として区別し、失敗には数えない。

## 既知の制限（段階 2 以降で扱う）

- 180 Ringing は FreeSWITCH が `ignore_early_media=true` の設定で 183 を返さないため未計測（応答側が 50 ms で即応答するため）。`answer_after` を伸ばせば 180/183 を受ける。
- DTMF（RFC 2833）は SDP で提示するだけで送出は段階 5。
- 再送タイマーはあるが、パケット損失環境での検証は未実施。
