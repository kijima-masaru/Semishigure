このステップで何をするか

Semishigure は、この PC の上で SIP 電話機（発信側 1 台と応答側の内線）を演じて PBX に登録し、内線どうしの通話を大量に張ります。あわせて PBX の管理用ポートにつないで通話数や CPU を記録します。そのために PBX 側で次の 3 つが通っている必要があります。

「保存して接続テスト」で確かめること

プロファイルを保存したあと、実際に PBX につないで次を確かめます。すべて通れば次のステップに進めます。

  • {{ guide.pbx.type==='asterisk' ? 'AMI' : 'ESL' }} にログインできる（アドレス、ポート、パスワードが正しい）
  • PBX の版、同時セッションの上限、いまの通話数が取れる
  • PBX プロセスの PID、CPU 使用率、スレッド数が取れる（「プロセス名」が正しい）
  • ログファイルの末尾が読める

SIP の疎通（登録と発信）は内線を作った後の「5. 事前チェック」で確かめます。

合格の条件

  • REGISTER が 200（応答側の内線ごと）
  • 発信 → 応答が 200 で確立し、応答側の内線のどれかに着信している
  • RTP が両方向で 20 パケット以上、音量（RMS）がある
  • BYE が 200

監視の項目が NG のとき

SIP の 4 項目が合格なら負荷検証は進められます。監視（ESL / AMI、イベント、プラグイン）の NG は PBX 側の channels や CPU が記録に残らないだけなので、「監視の NG を無視して進む」で先に進めます。
